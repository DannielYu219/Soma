# Soma 搜索能力调研

## 现状

- 对话是前端假数据。`src/demo.ts` 的 `demoReply` 用正则返回写死的回复，没有调用任何模型。
- 设置页已经预留两块：模型服务（OpenAI 兼容 / Anthropic，地址、模型名、密钥，仅存在浏览器 localStorage）和"本地后端"（地址，检查 `GET /health`，文案写明用于"对话处理与项目数据"）。
- 仓库里没有后端代码。所以"给 AI 加搜索"的前提，是先有一个真正的模型调用和工具调用循环。这一步不是搜索本身，但搜索依赖它。
- 已有一个先例：`tests/browser-smoke.mjs` 用独立的无头 Chrome 配合临时 profile，且"不连接、不激活用户窗口"。这和后面要做的子 Agent 浏览器是同一种隔离方式。

## 产品哲学约束

这些约束直接决定方案形态：

1. 安静。搜索过程只给一行状态（复用现有的 `presence` 指示），不展示逐步的工具日志。
2. 来源可见但收起。引用放在回复下方的折叠列表里，形态参照现有的 `project-link`。
3. 范围限定在本次对话。搜索结果属于这次对话，不做全局索引。
4. 密钥不同步、不落盘到后端。
5. 不静默上传内容。搜索词会发给搜索服务，这一点要在设置里写清楚。

## 搜索来源的选择

| 方案 | 说明 | 优点 | 风险 / 限制 |
|---|---|---|---|
| 模型服务商内置搜索 | Anthropic、OpenAI 等提供服务端搜索工具 | 接入最快，不需要额外服务 | 依赖服务商；本次未能核实其最新参数与计费（抓取文档失败） |
| 搜索 API | Brave、Tavily、Serper、Google Custom Search 等 | 返回结构化 JSON，稳定 | 多数需要付费或有配额；**Bing Search API 已于 2025-08-11 退役**（已核实，见 Microsoft Learn 页面） |
| 自托管 SearXNG | 聚合多个引擎，提供 JSON 输出 | 本地运行，无 API 费用，和"安静、可控"一致；官方文档已核实支持 `format=json` 与 `q`、`language`、`time_range` 等参数 | 需要自己部署；上游引擎会限流，偶尔出验证码 |
| 无头浏览器搜索 Google / Bing | 子 Agent 打开搜索页，读取结果页 | 能看到真实结果页，也能处理需要交互的页面 | Google 与 Bing 的自动化访问通常受条款限制，且容易触发验证码，选择器也会变；不适合当唯一来源 |

推荐组合：SearXNG（或一个搜索 API）负责"找"，无头浏览器子 Agent 负责"读"。浏览器只用于打开具体页面、读正文，不用来硬抓 Google 结果页。这样脆弱的部分最少。

## 子 Agent 的设计

子 Agent 是一次独立的模型调用循环，由后端执行。

- 输入：一个任务描述，加上预算（例如最多 8 步、90 秒、5 个页面）。
- 工具：`search(query)`、`open(url)`、`extract(url)`。没有写文件、提交表单、访问项目数据或记忆的工具。
- 环境：每个任务使用全新的临时 profile，不带用户浏览器的 cookie，不登录任何账号。
- 输出：结构化报告 `{ summary, sources: [{title, url, used_for}], unresolved, stopped_reason }`。主模型只看到这份报告，不看到网页原文，并基于报告作答和引用。
- 汇报：完成后把报告作为一次工具结果交回主对话。运行中只通过流式事件推送一行状态。

### 密钥放在哪

现在模型密钥只在浏览器里。要让子 Agent 在后端跑模型循环，后端必须拿到密钥。两个选项：

- A：主循环留在浏览器，后端只暴露工具端点（`POST /search`、`POST /open`）。改动最小，密钥位置不变。缺点是浏览器关掉，子 Agent 任务就中断。
- B：子 Agent 循环放在后端。密钥随每次任务请求体传入，不写入磁盘。任务可以跑完再汇报，但密钥多经过一次本地后端。

我倾向先做 A，等任务变长、需要后台跑时再切到 B。

## 安全与隔离

- **防 SSRF**：`open` 和 `extract` 必须拒绝回环地址、内网段（10.x、172.16–31.x、192.168.x、169.254.x）和 `localhost`。否则网页内容可以把子 Agent 引向本机的后端和其他服务。
- **提示注入**：网页正文一律作为数据，不作为指令。子 Agent 没有任何写或发送类工具，所以即使被注入，影响范围也只是读到错误信息。
- **资源上限**：步数、时长、页面数都有硬上限，超出即停止并在报告的 `stopped_reason` 里说明。
- **验证码**：遇到验证码时停止，并在界面提示用户在浏览器窗口里完成，而不是尝试绕过。
- **日志**：搜索词和访问的 URL 只保存在本次对话里，不写入全局日志。

## 分阶段路线

1. **P0：模型调用与工具循环**。在本地后端实现一次真正的对话调用，支持工具定义和工具结果回填。没有这一步，后面都无法接入。
2. **P1：单次搜索工具**。接入 SearXNG 或一个搜索 API，返回标题、URL、摘要。前端增加一行搜索状态和折叠来源列表。
3. **P2：子 Agent 与无头浏览器**。使用系统 Chrome 或 Playwright，正文提取用 Readability 类库，不做整页截图（省 token）。加入上面的所有限制。
4. **P3：后台化**。如果任务需要分钟级，改为后端执行（方案 B），并允许关闭页面后再回来查看报告。

## 尚未核实的内容

- Anthropic 与 OpenAI 内置搜索工具的当前参数、计费与可用模型。两次抓取官方文档都失败（一次是跨域重定向，一次是网络错误）。
- Google Custom Search JSON API 的当前可用性。抓取失败。
- Brave、Tavily、Serper 的价格和免费额度。
- Google 搜索自动化条款的最新原文。本文只说"通常受限"，没有引用原文。

## 2026-11-04 后端实测更新

当前已实现真实后端搜索循环。当天 20:55（Asia/Shanghai）用现有 Python launcher 临时运行本地 SearXNG，通过后台 HTTP 查询 `2026年11月4日 新闻`，未调用付费模型。`searchWeb` 耗时约 6.38 秒，按当时默认上限取得 5 个合法 HTTP(S) 来源；后续诊断响应共有 21 条，结果引擎为 360search、DuckDuckGo、Sogou。来源包括法治日报 2026-11-04 版面、山东省政府当日发布会预告和央视当日秋粮报道；部分靠前结果日期不符，主模型仍须核对发布日期与相关性。

本次 Google 返回 403 access denied、Brave 返回 429 too many requests（各暂停 180 秒），首次 DuckDuckGo 出现 CAPTCHA，后续请求有结果。配置各引擎超时为 10 秒，本次失败主要是上游限制。以上仅是一次观测，不保证引擎持续可用。验证前默认 8787/8888 未运行，已有 8791 服务 `/search` 返回 404；未修改或停止该服务，本次临时启动的搜索实例验证后已退出。

修复后委托查询必定执行；每个查询最多尝试两次，子助手最多两轮、四个去重查询，整次子搜索预算 75 秒。模型不调用工具或整理失败时保留真实原始检索记录，全部失败则明确报告无法核实，不能生成伪证据。默认结果数提高为 8，保留显式配置；摘要片段最多 800 字符，每次查询交接资料最多 16000 字符。请求日期按系统时区写入消息尾部，保持 system 前缀稳定。
