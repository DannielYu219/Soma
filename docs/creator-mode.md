# Creator Mode：导出与修改日志

选中章节正文后，点击选区附近浮现的“添加到对话”胶囊按钮，即可把原文添加到聊天输入框上方，支持多个引用及发送前移除。Agent 收到章节 id、正文路径、版本、精确字符区间及行列，无需再次搜索相同段落。已发送的引用随消息保存，编辑重发和导出会话时保留；待发送引用也随会话恢复。发送前文稿有变化时，使用原文及前后文核对当前位置；无法唯一定位或章节已删除时明确标记失效，避免误改重复文本。

正文高度由与编辑框同排版的隐藏文本层撑开，避免每次输入先把全部正文高度归零再恢复造成滚动跳动。长文输入、换行、删除以及分栏宽度改变均保持自然布局。

Creator Mode 顶部的导出按钮可选择 Word 文档（.docx）或 Markdown（.md）。导出全部章节，按文稿顺序保留作品标题、章节标题、正文和空行；不会导出聊天或修改历史。DOCX 在浏览器本地生成，无额外运行服务或依赖。

顶部时钟图标打开修改日志。作品改名、章节标题/正文编辑、章节新增/删除/重排，以及已采纳的 AI 修改，都会留下版本号、时间、作者和类似 Git 的行差异。短时间内同一字段连续输入合并为一次差异；切换章节和未采纳的 AI 建议不计入。日志与所属会话一起保存，旧会话首次编辑时自动开始记录。

AI 在下一次发送消息时收到自上次请求以来尚未观察的近期差异，然后收到当前完整文稿。该信息仅放入当前用户消息尾部，保持 system、工具和历史消息前缀稳定。不会因每次按键自动发起模型请求。生成期间继续编辑不会并入本次已发送的版本；后续请求仍能看到这些新差异。请求失败时保留未观察状态。冲突建议只有用户采纳后才记入修改日志。

日志是轻量近期记录，最多保留 80 条且序列化日志不超过 240,000 字符；单次 AI 差异上下文最多 20,000 字符，超限会明确提示并以完整现稿为准。不是 Git 仓库，也不提供分支、提交或历史回滚。

验证：`npm run build`；`npm test`。可用 `CREATOR_DOCX_PYTHON=/path/to/bundled/python3 npm test` 额外运行 python-docx 的真实重开校验。已通过 ego-lite 实测导出菜单、文件下载、正文增删差异及刷新恢复。

## 文本写作与歌词写作

Creator Mode 顶部提供“文本写作 / 歌词写作”切换；旧文稿默认使用文本写作。歌词写作在每个正文逻辑行左侧显示目标数输入框及“字 / 音节”单位选择，包括空行和末尾新行。目标可填写 1–999 的整数，留空表示不限。自动折行仍属于同一逻辑行，不会增加额外目标框。控件跟随正文换行及分栏宽度变化对齐，正文仍可连续编辑和跨行选中引用。

模式和目标随所属会话保存；切回文本写作会隐藏控件并保留目标，切回歌词写作后恢复。插入或删除连续行时，保留未改动前后行的目标；同一行改写会保留该行目标，新增行默认不限。模式切换和目标修改会进入修改日志并增加文稿版本，沿用生成期间修改的冲突保护。

文稿新增 `writingMode: 'text' | 'lyrics'`；章节新增 `lineTargets` 数组，从第 1 行起对应 `text.split('\n')`，每项为 `null` 或 `{ count: number | null, unit: 'characters' | 'syllables' }`。直接对话及后台对话任务都会将模式和目标发送给 Agent；`update_creator` 的工具说明和格式也包含这些字段，要求 AI 遵循每行目标，增删行时同步维护数组。旧格式 AI 响应省略这些字段时，服务端会保留原模式并按新正文调整目标位置。这里只存储目标，不对自然语言的实际音节数进行自动判断。

验证覆盖：模式切换、存储往返、两种单位、空行、插入/删除/替换行、请求快照、三个模型协议中的 Agent 上下文、AI 工具修改后保留约束、无效字段拒绝；浏览器实测刷新恢复、桌面及 390px 窄窗口布局、长行自动折行后的目标对齐。

## 导入文稿

Creator Mode 顶部的导入按钮支持 TXT、Markdown（.md / .markdown）和 Word（.docx）。TXT 按原文件名作为作品标题，并可识别常见中文“第 X 章”及英文 “Chapter N” 章节标题；Markdown 读取第一个一级标题作为作品名、二级标题作为章节，未检测到章节时保留为单章；DOCX 读取 Title 与 Heading 1 样式，并保留段落、换行和制表符。文件仅在本机读取与解析，不会上传。

导入会替换当前作品标题、章节和正文，但保留会话聊天记录及当前文本 / 歌词写作模式；当前作品已有标题、章节或正文时会先询问确认，并写入修改日志。支持最大 20 MB 的文件和最大 80 MB 的 DOCX 解压内容，最多 100 章、每章最多 100,000 字符。文本文件按 UTF-8 读取；受保护或损坏的 DOCX 会给出错误，不会替换现稿。歌词约束不作为普通文件元数据导出，导入的新章节默认没有逐行目标。
