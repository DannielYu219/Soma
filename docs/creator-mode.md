# Creator Mode：导出与修改日志

选中章节正文后，点击选区附近浮现的“添加到对话”胶囊按钮，即可把原文添加到聊天输入框上方，支持多个引用及发送前移除。Agent 收到章节 id、正文路径、版本、精确字符区间及行列，无需再次搜索相同段落。已发送的引用随消息保存，编辑重发和导出会话时保留；待发送引用也随会话恢复。发送前文稿有变化时，使用原文及前后文核对当前位置；无法唯一定位或章节已删除时明确标记失效，避免误改重复文本。

正文高度由与编辑框同排版的隐藏文本层撑开，避免每次输入先把全部正文高度归零再恢复造成滚动跳动。长文输入、换行、删除以及分栏宽度改变均保持自然布局。

Creator Mode 顶部的导出按钮可选择 Word 文档（.docx）或 Markdown（.md）。导出全部章节，按文稿顺序保留作品标题、章节标题、正文和空行；不会导出聊天或修改历史。DOCX 在浏览器本地生成，无额外运行服务或依赖。

顶部时钟图标打开修改日志。作品改名、章节标题/正文编辑、章节新增/删除/重排，以及已采纳的 AI 修改，都会留下版本号、时间、作者和类似 Git 的行差异。短时间内同一字段连续输入合并为一次差异；切换章节和未采纳的 AI 建议不计入。日志与所属会话一起保存，旧会话首次编辑时自动开始记录。

AI 在下一次发送消息时收到自上次请求以来尚未观察的近期差异，然后收到当前完整文稿。该信息仅放入当前用户消息尾部，保持 system、工具和历史消息前缀稳定。不会因每次按键自动发起模型请求。生成期间继续编辑不会并入本次已发送的版本；后续请求仍能看到这些新差异。请求失败时保留未观察状态。冲突建议只有用户采纳后才记入修改日志。

日志是轻量近期记录，最多保留 80 条且序列化日志不超过 240,000 字符；单次 AI 差异上下文最多 20,000 字符，超限会明确提示并以完整现稿为准。不是 Git 仓库，也不提供分支、提交或历史回滚。

验证：`npm run build`；`npm test`。可用 `CREATOR_DOCX_PYTHON=/path/to/bundled/python3 npm test` 额外运行 python-docx 的真实重开校验。已通过 ego-lite 实测导出菜单、文件下载、正文增删差异及刷新恢复。
